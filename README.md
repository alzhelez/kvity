# Квиты

Аукцион домашних дел для пары или соседей. У каждого дела есть цена неприятности в баллах. Вы обмениваетесь делами («я мою посуду неделю, если ты разберёшь балкон»), весы показывают, честен ли обмен, а общий счёт — кто сколько сделал.

Приложение работает без сервера и без аккаунтов. Все данные лежат на телефонах, а сверяются через QR-код или текстовый код в мессенджере.

## Запуск на телефоне

Нужен Node.js 20 или новее.

```bash
npm install
npx expo start
```

На телефоне установите **Expo Go** (App Store / Google Play) и отсканируйте QR-код из терминала. Телефон и компьютер должны быть в одной Wi-Fi сети. Если не получается, запустите `npx expo start --tunnel`.

Проект собран на Expo SDK 58, поэтому Expo Go должна быть свежей версии.

## Отдельное приложение (APK / iOS)

Сборка идёт в облаке EAS, Android Studio и Xcode не нужны:

```bash
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build -p android --profile preview   # APK для установки напрямую
npx eas-cli@latest build -p ios                         # нужен аккаунт Apple Developer
```

Для APK в `eas.json` у профиля `preview` укажите `"android": { "buildType": "apk" }`.

## Как пользоваться вдвоём

1. Первый человек создаёт дом: вводит имена, отмечает себя, включает стартовый список дел.
2. Второй ставит приложение и нажимает «Присоединиться по коду». Первый открывает «⇄ Синхр. → Мой код» (полный код включён автоматически, пока соседей нет), второй сканирует.
3. Дальше каждый работает на своём телефоне: предлагает сделки, принимает их, отмечает сделанное.
4. Чтобы увидеть изменения друг друга, время от времени синхронизируйтесь: один показывает код, другой сканирует, потом наоборот. Если вы не рядом, отправьте код текстом через «Отправить текстом» и вставьте его на вкладке «Текстом».

Если на экране написано «Код неполный», включите у отправителя переключатель «Полный код».

## Как устроена синхронизация

- Каждая запись (дело, сделка, отметка о выполнении, список участников) хранит время изменения и id устройства-автора. При слиянии побеждает более поздняя версия.
- Каждое устройство помнит вектор знаний: до какого момента у него есть все изменения каждого автора. Соседи присылают друг другу эти векторы, поэтому в код попадают только изменения, которых у соседа ещё нет.
- Получатель проверяет, что у него есть всё, на что опирается код. Если нет, код не применяется и приложение просит полный.
- Длинный код сжимается (deflate) и показывается несколькими QR-кадрами по очереди, сканер собирает их сам.
- Задачи по сделке, которую в итоге отозвали или отклонили (например, при одновременных правках на двух телефонах), в счёт не идут.

## Структура

```
App.tsx                 главный экран, вкладки, модальные окна
src/model.ts            типы данных, подсчёт очков, честность обмена, тексты
src/sync.ts             слияние, векторы знаний, кодирование, QR-кадры
src/store.tsx           хранилище (AsyncStorage) и действия
src/theme.ts            цвета светлой и тёмной темы, шрифты
src/ui.tsx              кнопки, степпер, весы, модальный лист, тост
src/screens/            Счёт, Торг, Дела, Цены, конструктор сделки, синхронизация, первый запуск
scripts/sync-check.ts   прогон синхронизации трёх телефонов
```
